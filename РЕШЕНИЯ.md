## 1. Название

Пять вариантов: **Тропа**, Перевал, Мостик, Просвет, Сквозняк.

Выбрал **«Тропа»**: короткое, легко читается и произносится, про «путь» — как раз то, что делает VPN.
Название задано в одном месте — файл `brand.json`, поле `name` (и `tagline` — подпись под названием).
Поле `id` (латиницей) не трогать: от него зависит папка с настройками, и при смене названия ключи не потеряются.

## 2. Движок

- **sing-box 1.14.2** (последний стабильный на момент работы), официальная сборка с GitHub: `github.com/SagerNet/sing-box/releases`.
- Автор **не публикует файл контрольных сумм**. Поэтому я скачал нужные архивы, посчитал SHA-256 и записал в `scripts/singbox-checksums.json`.
  Скрипт `npm run fetch:singbox` на каждой загрузке сверяет сумму и **не устанавливает файл, если она не совпала**.
  GitHub показывает SHA-256 рядом с каждым файлом на странице выпуска — можно сверить глазами.
- В установщик кладётся только `sing-box.exe`. Файл `libcronet.dll` из архива не нужен (он только для «naive»-подключений, которых у нас нет) — проверил, что без него движок работает. Драйвер туннеля **wintun уже вшит** в `sing-box.exe` (проверил по исходникам: `go:embed`), отдельный файл не нужен.
- Свой сетевой код не писал: приложение собирает файл настроек, запускает движок, останавливает и читает состояние через его управляющий интерфейс.

## 4. Ключи

- Поддержаны: `vless` (в том числе Reality и Vision), `vmess` (старый вид в base64 и новый со ссылкой), `trojan`, `ss` (старый и новый вид, шифры 2022, плагины obfs и v2ray-plugin), `hysteria2`/`hy2` (с маскировкой salamander и перебором портов), `tuic`, `anytls`, ссылки-подписки, готовый файл sing-box.
- **Готовый файл sing-box**: из него берутся только серверы. Маршруты, DNS и входящие подключения из чужого файла отбрасываются — приложение строит свои, иначе режимы и правила «мимо VPN» не сработали бы. Цепочки серверов (`detour`) не поддерживаются — человеку об этом честно говорится.
- **Не поддерживается, и об этом пишется простыми словами**: транспорт `xhttp` (движок его не умеет), mKCP, «новое шифрование VLESS», формат подписки Clash (YAML). Для Hysteria2 отпечаток сертификата `pinSHA256` движок проверить не может — ключ добавляется с предупреждением.
- Названия серверов очищаются от флагов-эмодзи: **в Windows они рисуются как две буквы**. Вместо них — настоящие картинки флагов (набор `flag-icons`, лежит внутри программы, из интернета не грузится). Страна угадывается по флагу в названии, коду страны или названию страны/города.
- Если в названии нет подсказки о стране, показывается нейтральный глобус.

## 5. Хранение и секреты

- Ключи (и адреса подписок — в них часто спрятан токен) шифруются средствами системы: в Windows это DPAPI через `safeStorage` Electron, привязка к вашей учётной записи Windows. Проверено тестом: в файле данных нет ни паролей, ни идентификаторов, ни ссылок.
- **Если шифрование недоступно, ключ не сохраняется вовсе** (с понятным сообщением). Открытым текстом ничего не пишется.
- Во временном файле настроек для движка секреты, конечно, есть (иначе он не подключится): файл создаётся с правами только для вас и **удаляется при отключении**.
- В журнал и на экран ключи целиком не попадают: есть очистка (`core/redact.ts`) — маскируются ссылки, идентификаторы, пароли, «хвосты» адресов. В разделе «Для специалиста» итоговые настройки показываются с замазанными секретами.
- Телеметрии нет. Окно запрещено вести куда-либо кроме своих файлов (адреса, всплывающие окна и переходы заблокированы; политика безопасности страницы разрешает только свои ресурсы).

Запрос идёт **через VPN-сервер**, а не напрямую, и ничего про вас не передаёт. Если хочешь убрать — скажи, тогда придётся показывать «Работает» сразу после запуска движка.

Если в режиме «Браузер и программы» — ещё один запрос к `api.country.is` **напрямую**, чтобы сравнить с адресом через VPN. Ничего про вас не передаётся.

## 7. Режимы

- **«Только браузер и программы» (системный прокси)**: приложение само прописывает прокси в реестре Windows и сообщает системе об изменении; прежние настройки прокси запоминаются и возвращаются при отключении. Домашняя сеть в список исключений добавлена. Если программу закрыли аварийно, при следующем запуске она убирает «свой» прокси, чтобы у вас не пропал интернет.
- В любом режиме у движка есть локальный вход `127.0.0.1` (только внутри компьютера): через него приложение само делает проверки «как браузер».
- **«Весь компьютер» (TUN)**: **только IPv4 по умолчанию**. Причина: на компьютерах, где IPv6 отключён, туннель с IPv6-адресом просто не запускается (я с этим столкнулся в тесте). Со `strict_route` недоступный IPv6 «не достижим» — программы переключаются на IPv4, утечки нет. IPv6 можно включить в «Для специалиста».
- Домашняя сеть (`10.*`, `172.16–31.*`, `192.168.*`, `169.254.*`, многоадресные) в туннель не попадает вообще и дополнительно всегда идёт напрямую по правилу.

## 8. Правила «мимо VPN»: порядок

Сверху вниз, первое подходящее выигрывает:

1. Домашняя сеть и имена `.local`, `.lan` → напрямую.
2. Заблокированные в России СМИ (набор `category-media-ru-blocked`) → **всегда через VPN, даже если домен `.ru`**. Эти сайты нельзя пускать напрямую — не откроются.
3. Ваш список «всегда через VPN».
4. Ваш список «всегда напрямую».
5. Программы мимо VPN (по имени исполняемого файла).
6. Российские зоны `.ru`, `.рф` (записывается как `xn--p1ai`), `.su` → напрямую.
7. Российские наборы доменов (Яндекс, VK, Mail.ru, Госуслуги, банки, магазины и др.) → напрямую.
8. Российские IP-адреса → напрямую.
9. Всё остальное → через VPN.

Решения:
- **Российские IP-адреса сопоставляются только там, где адрес известен заранее** (в туннеле и для прямых IP). Я намеренно не использую действие `resolve`: если бы удалённый DNS на миг не ответил, движок **отвергал бы вообще все соединения** (проверил по исходникам). Надёжность важнее.
- Если домен `.ru` заблокирован в России (бывает), добавь его в «всегда через VPN».
- Вшитый набор списков лежит в `resources/rules` (источник и дата — в `SOURCE.md`). Обновляются сами раз в 3 дня; битый скачанный файл не ломает запуск — берётся вшитый.

## 9. DNS

- Для российских сайтов — «прямой» DNS (по умолчанию системный), для остальных — DoH `1.1.1.1` **через VPN**: провайдер не видит, какие зарубежные сайты вы открываете.
- Выключатель «защита от утечки DNS»: выключено — всё спрашивается у прямого DNS.
- Адрес сервера VPN, если он задан именем, ищется прямым DNS (иначе курица и яйцо).

## 10. Внешний вид

- Три набора: **Сияние** (бирюза + фиолет), **Закат** (коралл + малина), **Хвоя** (изумруд + золото) — в тёмной и светлой темах. Цвет ошейника у собаки подстраивается под набор.
- Шрифт Manrope (SIL OFL) лежит внутри программы.
- Уровни анимации: «Все», «Спокойные» (без тяжёлых фоновых эффектов) и «Выключены» — для слабых компьютеров. Подсказка у настройки это объясняет.
- Анимация большой кнопки у каждого состояния своя: выключено — «дышит»; подключаюсь — крутятся дуги, частицы слетаются к центру; работает — расходятся волны, летают точки, вспышка при включении; ошибка — вздрагивает.

## 11. Шелти (собака-помощник) — добавлено по просьбе

- Нарисована кодом (SVG), без чужих картинок: соболиный шелти с белым воротником.
- Живёт внизу боковой панели. Следит глазами и головой за курсором, моргает, дремлет, если долго не трогать мышь, виляет хвостом, когда VPN работает, прижимает уши при ошибке.
- Наведите мышку на любой элемент — в облачке над собакой появится простая подсказка. Подсказки есть у меню, большой кнопки, переключателя режимов, плиток, графика, карточек серверов, настроек.
- Облачко намеренно сделано **над собакой, внутри боковой панели**: так оно никогда не закрывает то, на что вы навели мышку.
- Выключается в «Настройках» → «Помощник».

## 12. Проверка связи и ошибки

- «Подключено» показывается только после того, как через сервер реально прошёл запрос. Если за ~20 секунд связи нет — «Сервер не отвечает. Возможно, ключ устарел или введён с ошибкой».
- Все ошибки движка переводятся в человеческие фразы (`shared/humanErrors.ts`), технические подробности остаются только в журнале.
- При обрыве: если включено «Переподключаться при обрыве» — попытки с нарастающей паузой (1,5 → 3 → 6 → 12 → 30 с), пока человек не нажмёт «Выключить».

## 13. Прочее

- Окно запускается в единственном экземпляре; пока трея нет, крестик закрывает программу; когда появится трей, крестик будет сворачивать в него, а выход — отдельной командой.
- Уведомления Windows включены только на Windows: на Linux (где я разрабатывал) без службы уведомлений они «замораживали» программу.
- Любая непредвиденная ошибка в главном процессе не показывает системное окно с ошибкой (оно блокирует программу), а записывается в журнал.
- Ключи для проверки без настоящего сервера: тесты поднимают **настоящий sing-box-сервер на localhost** для 14 вариантов подключений и гоняют через него реальный трафик.

## 14. Права администратора (этап 2)

Режиму «Весь компьютер» нужны права администратора. Варианты были такие:
1. Всегда запускать программу «от администратора» — Windows спрашивало бы при каждом запуске. Плохо для не-айтишника.
2. Запускать с повышением только движок — не получилось бы потом его остановить из обычной программы и читать его вывод.
3. **Выбрано:** один раз (с обычным окном Windows «Разрешить?») создать задачу планировщика «запускать программу с наивысшими правами». Дальше программа запускается этой задачей **без вопросов**. Разрешение можно забрать в «Настройках».

Как это складывается:
- Человек выбирает «Весь компьютер» → программа объясняет по-человечески, зачем это нужно → «Разрешить» → Windows спрашивает один раз → программа перезапускается уже с правами и включается в нужном режиме.
- Если человек отказал в окне Windows — режим не включается, объяснение спокойное, ничего не ломается.
- Если при запуске выбран «Весь компьютер», а права ещё не получены и разрешение уже выдавалось, обычная копия сама запускает копию с правами и закрывается (так же работает и автозапуск с Windows).
- Стандартная защита Electron от второго запуска не умеет «достучаться» от обычной копии до копии с правами (Windows не пускает сообщения «вниз по уровню защиты»). Поэтому я сделал свою: первая копия слушает порт **только на 127.0.0.1** и записывает его вместе с секретным словом в файл в своей папке данных; вторая копия читает файл, просит «покажись» и закрывается.
- Задача создаётся без расписания (не стартует сама), только по запросу.

## 15. Аварийное завершение (этап 2)

Нашёл тестом: закрыть программу «не нашим» путём (завершение системы, команда «выйти» от ОС) можно было так, что движок оставался в фоне, а системный прокси Windows — включённым «в никуда» (интернет пропал бы). Сделано три слоя защиты:
1. **При любом выходе** программа останавливает движок и возвращает системный прокси.
2. **При следующем запуске** программа убирает «хвосты»: если прокси остался включённым после аварии — возвращает прежний; если в фоне остался забытый движок — останавливает его (но только убедившись, что под этим номером процесса именно наш `sing-box`, чужие процессы не трогаются).
3. Прежний системный прокси человека (например, рабочий) запоминается при включении и возвращается при отключении, а «наш» старый адрес после аварии за «прежний» не считается.

## 16. Обновление списков (этап 2)

- Списки для российских сайтов лежат вшитыми (`resources/rules`); приложение само обновляет их из GitHub раз в 3 дня (проверка при запуске, через 25 секунд, и затем раз в 6 часов). Если напрямую GitHub недоступен, а VPN включён — попытка через VPN.
- Каждый скачанный файл проверяется (метка «SRS» и размер); плохой отбрасывается. Если же набор правил по какой-то причине не принят движком, при подключении используются вшитые списки — подключение из-за списков не сломается.
- Обновлённые списки применяются при следующем подключении (движок не умеет подменять их на ходу).

## 17. Подписки (этап 3)

- Ссылка на подписку добавляется той же кнопкой «Вставить ключ или подписку» (а также по Ctrl+V в любом месте окна): программа сама понимает, что это ссылка, и ставит её на обновление. Ссылки-«обёртки» других программ (`sing-box://import-remote-profile`, `happ://…`, `v2rayn://…` и т. п.) тоже понимаются.
- Запрашиваем список с именем клиента вроде v2rayN, потому что так большинство панелей отдаёт обычный список ключей, а не формат Clash. Если всё же пришёл формат Clash (YAML) — честно пишем, что такой формат программа не читает.
- Из заголовков берутся: название подписки (`profile-title`), остаток трафика и срок (`subscription-userinfo`), как часто обновлять (`profile-update-interval`, по умолчанию 12 часов). Остаток трафика показывается полоской у подписки.
- **Обновление сохраняет то, что настроил человек.** Серверы после обновления узнаются: по ключу целиком; потом по «тип + адрес + порт + название от поставщика» (так переживаются смены ключей у того же сервера — поставщики любят их менять); потом по «тип + адрес + порт», если этот сервер один. Для узнанного сервера новые ключи записываются на то же место, а имя человека, «звёздочка» и выбор остаются. Новые серверы добавляются, исчезнувшие — убираются, а тот, к которому сейчас подключены, остаётся до отключения (чтобы не оборвать связь).
- **Сервер, удалённый человеком из подписки, при обновлении не возвращается** (запоминается отпечаток и «адрес+название»).
- Неудачное обновление **не стирает серверы**: у подписки появляется понятная пометка («Сайт подписки не пустил…»), а программа пробует позже сама. После неудачи — не чаще раза в полчаса, после успеха — раз в срок поставщика, проверка раз в 10 минут (первая — через 15 секунд после запуска). Фоновые обновления тихие: человеку приходят только сообщения о проблемах (значок у подписки), а не «обновлено» каждые 12 часов.
- Сайт подписки в стране может быть заблокирован: если VPN уже включён, загрузка при необходимости идёт **через него** (сначала напрямую, потом через VPN); в сообщении об ошибке есть подсказка «включите VPN через другой ключ и повторите».
- Адрес подписки (в нём обычно секретный токен) шифруется так же, как ключи, и нигде не показывается: на экране — только «https://сайт/…». Проверено тестом: токена нет ни в состоянии окна, ни в файле данных, ни в журнале.
- Удаление подписки удаляет и её серверы (понятным окном с числом серверов). Отдельного режима «оставить серверы» нет: они стали бы «сиротами», которые никогда не обновятся.

## 18. Проверка задержки серверов (этап 3)

- Один временный запуск движка на весь список серверов: у каждого сервера **свой локальный вход** на 127.0.0.1, и всё, что в него пришло, уходит строго через этот сервер. Запрос проходит весь путь «как у браузера» (шифрование → сервер → интернет), поэтому число — это то, что человек почувствует, а не «ответил ли порт».
- Время берётся лучшее из двух запросов (первый включает поиск адреса сервера и рукопожатие, он завышает).
- Если один ключ «сломан» (движок не принимает), он не должен лишать проверки остальных: при отказе общего файла ключи проверяются по одному, виноватые получают «ключ не подходит», остальные проверяются.
- Серверы, которые не отвечают за 6 секунд, получают «не отвечает». Параллельно проверяется до 12 серверов.
- Временный движок ничего не меняет в системе (ни туннеля, ни прокси), поэтому проверка работает и при включённом VPN. Файл с секретами для него живёт секунды и удаляется (в том числе при закрытии программы посреди проверки).
- **При первом заходе на страницу «Серверы» задержка проверяется сама** (один раз за запуск) и после добавления нового ключа тоже — человеку не нужно ничего нажимать. Вручную: «Проверить задержку» (все) и значок молнии на карточке (один сервер). Порядок «Быстрые сверху» — по результатам (любимые всегда сверху).

## 19. QR-код (этап 3)

- QR-код ключа или подписки показывается **только по просьбе**, и сначала — окно с предупреждением («в этом коде ваш ключ целиком, показывайте только тем, кому доверяете»); сам код появляется после нажатия «Показать код» и **сам прячется через 90 секунд**. Рисуется в основной части программы, картинка существует только пока окно открыто; в журнал попадает лишь «показан QR-код», без содержимого.
- Если у сервера нет исходной ссылки (он добавлен из готового файла настроек sing-box) — QR сделать нельзя, и пункт в меню просто не показывается. Слишком длинный ключ (больше ~2200 знаков) в QR не помещается — тоже понятное сообщение.

## 20. Кнопка «Проверить, всё ли работает» (этап 3)

Видна только при включённом VPN. Четыре шага, каждый со своим результатом простыми словами, в конце итог одной фразой:
1. **Связь с сервером** — запрос до интернета через сервер; медленнее 600 мс — замечание, нет ответа — проблема.
2. **Ваш адрес в интернете** — страна, под которой нас видят сайты. Проблема, если в режиме «Браузер и программы» адрес через VPN совпал с настоящим (значит, VPN не работает). Замечание, если видят из России, а сервер не в России. В режиме «Весь компьютер» настоящий адрес не сравнивается: программа сама идёт через туннель, и «настоящего» адреса не получить.
3. **Поиск адресов сайтов (DNS)** — движок сам спрашивает `whoami.akamai.net` по правилам DNS, из ответа видно, чей узел искал адрес, и страна этого узла. Если это Россия, а мы не в России — замечание с советом включить «Защиту от утечки DNS» (или «переподключитесь», если защита уже включена). В режиме «Браузер и программы» программы, которые сами ищут адреса сайтов, в эту проверку не попадают — про это нужно помнить.
4. **Российские сайты напрямую** — запрос к `ya.ru` и затем открытое соединение к нему, по которому **сам движок называет выход** (`direct` или `proxy`): так видно не «открылся ли сайт», а «ушёл ли он мимо VPN». Если настройка «Российские сайты напрямую» выключена — шаг показывает «так и задумано», российский сайт не трогается.
- Итог: «Всё работает…» (зелёный, с искрами), «В целом работает, но есть замечание…» (жёлтый) или «Есть проблема…» (красный; при проблеме с сервером — совет попробовать другой).
- Результат относится к конкретному подключению: при отключении исчезает сам. «Ещё раз» и «Закрыть» работают; повторный запуск во время идущей проверки игнорируется.
- Вся логика проверки не знает про сеть: всё нужное ей подаётся извне — поэтому она проверена на подставных ответах (все ветки), а ключевые куски — ещё и на настоящем движке.

## 21. Что поменялось по ходу этапа 3

- Окно «Серверы» и главный экран: если подключены к серверу, который уже не выбран в списке, на главном показывается именно подключённый сервер.
- Модальные окна: пока окно гаснет после закрытия, оно больше не перехватывает нажатия (раньше первое нажатие по меню сразу после закрытия окна пропадало — нашёл e2e-тестом).
- Тексты ошибок «серверов не найдено»: общая фраза больше не дублируется перед конкретной причиной.
- Тест `vless httpupgrade` на нагруженной машине изредка падал из-за **особенности самого движка** (на первом соединении сервер видел «unknown version: 233» — первый байт идентификатора; отдельно тест проходит десятки раз подряд). Для этого одного сценария тест делает **один повтор**, причина записана в комментарии. В самой программе первая проверка связи и так делает три попытки.

## 22. Защита: аварийная блокировка и защита DNS (этап 4)

- **Режим «Весь компьютер».** Пока VPN работает или переподключается, брандмауэр Windows закрывает исходящий интернет для всех, кроме: самого движка (`sing-box.exe` — чтобы он мог связаться с сервером), трафика из туннеля (с адреса туннеля) и домашней сети. Порядок: сначала создаются «калитки», потом закрывается всё остальное; прежние настройки брандмауэра запоминаются **до** изменений и возвращаются при выключении. Если VPN оборвался, туннеля нет — наружу ничего не уходит.
- **Режим «Браузер и программы».** Здесь защита слабее, и об этом честно написано на самой странице: при обрыве системный прокси остаётся указывать «в никуда», и браузеры и программы с поддержкой прокси замолкают. Игры и остальные программы так не остановить — для них нужен режим «Весь компьютер».
- **Обрыв без «переподключаться само»**: интернет **остаётся закрытым** (на главном экране — красная плашка «Защита держит интернет закрытым…», в уведомлении — то же). Раньше в этом случае защита молча снималась — это была бы утечка. Открыть интернет можно: большой кнопкой (подключиться), выключателем защиты или кнопкой «Починить интернет».
- **Первое подключение не удалось** (неверный ключ): защита снимается, человек не остаётся без интернета — настоящего VPN у него и не было.
- Если защиту не удалось включить (Windows не дала изменить правила) — VPN всё равно работает, а человеку сообщается: «если VPN оборвётся, интернет сам не отключится».
- При IPv6 в туннеле разрешены оба адреса туннеля.
- **«Починить интернет»** (страница «Защита»): останавливает VPN, **принудительно** снимает защиту (даже если программа «забыла», что включала её), возвращает системный прокси, убирает забытый движок. Нужна на случай сбоя. Та же уборка делается сама при каждом запуске после аварии, а выход из программы всегда всё возвращает.
- Если вручную: в PowerShell **от администратора** — `Set-NetFirewallProfile -Profile Domain,Private,Public -DefaultOutboundAction Allow`, затем `Get-NetFirewallRule -Group TropaKillSwitch | Remove-NetFirewallRule`.
- **Защита от утечки DNS** (включена по умолчанию): адреса сайтов ищутся через VPN (шифрованный DNS через сервер), а не у провайдера; российские сайты и домашняя сеть — через обычный DNS. Подробности — раздел 9.
- На странице «Защита» одной строкой видно состояние: зелёный щит — включена (весь компьютер), жёлтый — частично (только прокси-режим), красный — держит интернет закрытым, серый — выключена.

## 23. Значок в трее, закрытие, уведомления (этап 4)

- Значок возле часов (только Windows) показывает состояние **цветом**: выключено / подключаюсь / работает / тревога (нет связи с сервером, ошибка, интернет закрыт защитой). При наведении — слова: «Тропа: работает · Нидерланды». Меню правой кнопкой: включить / выключить (или отменить подключение), открыть окно, выйти. Без ключей пункт «Сначала добавьте ключ…» ведёт в окно. Щелчок по значку показывает или прячет окно.
- **Крестик сворачивает в трей** (включено по умолчанию, можно выключить в «Настройках»), но **только если значок реально появился**; иначе крестик закрывает программу — чтобы окно не пропало без возможности вернуть. В первый раз Windows показывает уведомление «программа осталась в трее».
- «Выйти» из меню значка и любой другой полноценный выход останавливают VPN и возвращают всё как было (раздел 15).
- Уведомления Windows: подключено, отключено, связь оборвалась (отдельная фраза, если интернет закрыт защитой), восстановилась, ошибка. Включаются и выключаются в «Настройках». Для них задан идентификатор программы Windows (иначе уведомления могли бы не показываться).

## 24. Запуск вместе с Windows и подключение при запуске (этап 4)

- **Автозапуск** — запись в разделе автозагрузки текущего пользователя (без прав администратора) с признаком «свёрнуто»: окно не выскакивает, программа сидит в трее. Работает **только в установленной программе на Windows**; из папки разработки (там запускался бы «голый» Electron) он не включается, а в «Настройках» этих пунктов на других системах нет. Если запись «слетела» (переустановка, перенос), при запуске она возвращается сама.
- **Режим «Весь компьютер» + автозапуск.** Права администратора программа получает через задачу планировщика (раздел 14). Автозапуск стартует обычную копию, она видит «выбран весь компьютер и разрешение есть» и запускает копию с правами. Той копии аргументы передать нельзя, поэтому «запустись свёрнутой» передаётся **запиской** в папке данных (живёт не дольше 90 секунд и читается один раз).
- Свёрнутый запуск, но значка в трее нет (например, система не показала) — окно **всё равно показывается**, чтобы программу можно было найти.
- **Подключаться при запуске**: через ~1,5 с после старта включает VPN через выбранный сервер. Сразу после загрузки Windows сеть может быть ещё не готова (Wi-Fi поднимается), поэтому при «сетевых» неудачах (сервер не отвечает, нет адреса, нет интернета) программа пробует ещё до четырёх раз с паузами 1,5 / 5 / 10 / 20 секунд. Не повторяет, если причина не сетевая (нет прав, неверный ключ). Как только человек сам нажал «включить/выключить» — автоподключение отступает.

## 25. Первый запуск — мастер из трёх шагов (этап 4)

- Показывается один раз (пока не нажато «Начать пользоваться» или «Пропустить»). Шаги: **1. Ключ** (кнопка берёт ключ или ссылку на подписку из буфера; показывает, что добавилось; без ключа можно идти дальше — «У меня пока нет ключа»), **2. Режим** (две большие карточки; «Браузер и программы» отмечен «Рекомендуем для начала»; «Весь компьютер» ведёт в то же объяснение про права, что и на главной), **3. Готово** (та же большая кнопка включает VPN прямо в мастере; два выключателя «запускать с Windows» и «подключаться при запуске»; Шелти представляется).
- Номер шага запоминается: если выбор «Весь компьютер» перезапустит программу с правами, мастер продолжится с того же места.
- Мастер можно пропустить в любой момент: всё то же есть на вкладках «Серверы» и «Настройки».

## 26. «Для специалиста» (этап 4)

- В «Настройках», **свёрнут**, пока человек сам не откроет. Внутри: DNS через VPN (готовые Cloudflare/Google/Quad9 или свой адрес), DNS для прямых запросов («system» или адрес), порт локального прокси, размер пакета (MTU), сетевой стек туннеля, IPv6 в туннеле, строгие маршруты, уплотнение соединений, подробность журнала, **итоговые настройки движка** (секреты заменены на ••••), **журнал** (обновляется сам, копируется, очищается), «Сбросить всё к стандартному».
- **Неверное значение не принимается**, под полем объясняется почему («Размер пакета (MTU) должен быть целым числом от 1280 до 9000»). Проверка одна и та же и в окне, и в основной части программы (`shared/advanced.ts`), так что подменить её нельзя. Для удалённого DNS «system» не принимается: запрос должен уйти через VPN.
- После изменения при включённом VPN подключение само перезапускается с новыми настройками. Итоговые настройки при работающем подключении показывают **настоящий** файл (с реальным портом), иначе — «так будет при подключении».
- Журнал и итоговые настройки очищаются от ключей, паролей и идентификаторов; адрес сервера в итоговых настройках виден (он нужен специалисту и не является секретом).

## 27. Установщик и лицензии (этап 4)

- Установщик **NSIS** (`electron-builder.config.cjs`, название и идентификатор — из `brand.json`): «нажал — установилось», **для текущего пользователя, без прав администратора**, ярлыки на рабочем столе и в «Пуске», по-русски; при удалении программы ключи и настройки **не стираются**. Рядом с программой кладутся движок, списки правил, значки трея и лицензии. Права администратора программа не требует при запуске — только режиму «Весь компьютер» и только по отдельному согласию (раздел 14).
- Сборка установщика на Linux невозможна (последний шаг требует `wine`), поэтому: (а) **GitHub Actions** (`.github/workflows/build-windows.yml`) собирает его на настоящей Windows; (б) локально на Windows — `npm run dist`; (в) переносимая версия «распаковал и запустил» собирается и без Windows — `npm run dist:portable`.
- **Подписи кода у проекта нет**, поэтому Windows (SmartScreen) при первом запуске установщика может написать «неизвестный издатель»: «Подробнее» → «Выполнить в любом случае». Подпись стоит денег (сертификат) — это решение за тобой.
- **Лицензии.** sing-box распространяется по GPL v3+ (с условием про название). Он поставляется **без изменений**, **отдельной программой** (`engine/sing-box.exe`), рядом лежит его лицензия, а ссылка на исходный код и список всего сторонне­го — в `THIRD-PARTY-NOTICES.md` (кладётся и в установленную программу). Если будешь распространять программу другим людям, это нужно сохранить.
