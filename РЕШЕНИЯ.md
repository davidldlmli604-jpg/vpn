# РЕШЕНИЯ

Сюда записано всё, что я решал сам, пока вопросов задавать было нельзя. Если с чем-то не согласен — скажи, поменяем.

## 1. Название

Пять вариантов: **Тропа**, Перевал, Мостик, Просвет, Сквозняк.

Выбрал **«Тропа»**: короткое, легко читается и произносится, про «путь» — как раз то, что делает VPN.
Название задано в одном месте — файл `brand.json`, поле `name` (и `tagline` — подпись под названием).
Поле `id` (латиницей) не трогать: от него зависит папка с настройками, и при смене названия ключи не потеряются.

## 2. Движок

- **sing-box 1.14.2** (последний стабильный на момент работы), официальная сборка с GitHub: `github.com/SagerNet/sing-box/releases`.
- Автор **не публикует файл контрольных сумм**. Поэтому я скачал нужные архивы, посчитал SHA-256 и записал в `scripts/singbox-checksums.json`.
  Скрипт `npm run fetch:singbox` на каждой загрузке сверяет сумму и **не устанавливает файл, если она не совпала**.
  GitHub показывает SHA-256 рядом с каждым файлом на странице выпуска — можно сверить глазами.
- В установщик кладётся только `sing-box.exe`. Файл `libcronet.dll` из архива не нужен (он только для «naive»-подключений, которых у нас нет) — проверил, что без него движок работает. Драйвер туннеля **wintun уже вшит** в `sing-box.exe` (проверил по исходникам: `go:embed`), отдельный файл не нужен.
- Свой сетевой код не писал: приложение собирает файл настроек, запускает движок, останавливает и читает состояние через его управляющий интерфейс.

## 3. Устройство проекта

| Папка | Что там |
|---|---|
| `core/` | Разбор ключей и сборка настроек. **Не зависит ни от Electron, ни от Node, ни от браузера** — это проверяется компилятором (`core/tsconfig.json` без единой подключённой библиотеки). Отсюда версия под Android возьмёт логику. |
| `electron/` | «Внутренности» приложения: запуск движка, хранилище, система Windows. |
| `src/` | Окно (React). |
| `shared/` | Типы, общие для окна и «внутренностей». |
| `tests/` | Автотесты. |

## 4. Ключи

- Поддержаны: `vless` (в том числе Reality и Vision), `vmess` (старый вид в base64 и новый со ссылкой), `trojan`, `ss` (старый и новый вид, шифры 2022, плагины obfs и v2ray-plugin), `hysteria2`/`hy2` (с маскировкой salamander и перебором портов), `tuic`, `anytls`, ссылки-подписки, готовый файл sing-box.
- **Готовый файл sing-box**: из него берутся только серверы. Маршруты, DNS и входящие подключения из чужого файла отбрасываются — приложение строит свои, иначе режимы и правила «мимо VPN» не сработали бы. Цепочки серверов (`detour`) не поддерживаются — человеку об этом честно говорится.
- **Не поддерживается, и об этом пишется простыми словами**: транспорт `xhttp` (движок его не умеет), mKCP, «новое шифрование VLESS», формат подписки Clash (YAML). Для Hysteria2 отпечаток сертификата `pinSHA256` движок проверить не может — ключ добавляется с предупреждением.
- Названия серверов очищаются от флагов-эмодзи: **в Windows они рисуются как две буквы**. Вместо них — настоящие картинки флагов (набор `flag-icons`, лежит внутри программы, из интернета не грузится). Страна угадывается по флагу в названии, коду страны или названию страны/города.
- Если в названии нет подсказки о стране, показывается нейтральный глобус.

## 5. Хранение и секреты

- Ключи (и адреса подписок — в них часто спрятан токен) шифруются средствами системы: в Windows это DPAPI через `safeStorage` Electron, привязка к вашей учётной записи Windows. Проверено тестом: в файле данных нет ни паролей, ни идентификаторов, ни ссылок.
- **Если шифрование недоступно, ключ не сохраняется вовсе** (с понятным сообщением). Открытым текстом ничего не пишется.
- Во временном файле настроек для движка секреты, конечно, есть (иначе он не подключится): файл создаётся с правами только для вас и **удаляется при отключении**.
- В журнал и на экран ключи целиком не попадают: есть очистка (`core/redact.ts`) — маскируются ссылки, идентификаторы, пароли, «хвосты» адресов. В разделе «Для специалиста» итоговые настройки показываются с замазанными секретами.
- Телеметрии нет. Окно запрещено вести куда-либо кроме своих файлов (адреса, всплывающие окна и переходы заблокированы; политика безопасности страницы разрешает только свои ресурсы).

## 6. Куда приложение ходит в сеть

Только сюда:

1. **VPN-сервер** (вы же сами его добавили).
2. **Адрес подписки** — если вы добавили подписку.
3. **Списки правил**: `raw.githubusercontent.com` (проекты SagerNet/sing-geosite и sing-geoip).
4. **Проверка адреса** (чтобы показать «ваш адрес сейчас виден как…»): `api.country.is`, запасной — `ipwho.is`. Запрос идёт **через VPN**, чтобы показать именно выходной адрес.
5. **Проверка связи** после подключения и раз в 20 секунд: крошечные страницы «204» — `cp.cloudflare.com`, `www.gstatic.com`, `connectivitycheck.gstatic.com`. ⚠️ Этого пункта в твоём списке не было. Я добавил его сам: без него нельзя отличить «подключено» от «движок запущен, но ключ не работает» (пример из задания — «Сервер не отвечает. Возможно, ключ устарел…» — как раз про это). Запрос идёт **через VPN-сервер**, а не напрямую, и ничего про вас не передаёт. Если хочешь убрать — скажи, тогда придётся показывать «Работает» сразу после запуска движка.

## 7. Режимы

- **«Только браузер и программы» (системный прокси)**: приложение само прописывает прокси в реестре Windows и сообщает системе об изменении; прежние настройки прокси запоминаются и возвращаются при отключении. Домашняя сеть в список исключений добавлена. Если программу закрыли аварийно, при следующем запуске она убирает «свой» прокси, чтобы у вас не пропал интернет.
- В любом режиме у движка есть локальный вход `127.0.0.1` (только внутри компьютера): через него приложение само делает проверки «как браузер».
- **«Весь компьютер» (TUN)**: **только IPv4 по умолчанию**. Причина: на компьютерах, где IPv6 отключён, туннель с IPv6-адресом просто не запускается (я с этим столкнулся в тесте). Со `strict_route` недоступный IPv6 «не достижим» — программы переключаются на IPv4, утечки нет. IPv6 можно включить в «Для специалиста».
- Домашняя сеть (`10.*`, `172.16–31.*`, `192.168.*`, `169.254.*`, многоадресные) в туннель не попадает вообще и дополнительно всегда идёт напрямую по правилу.

## 8. Правила «мимо VPN»: порядок

Сверху вниз, первое подходящее выигрывает:

1. Домашняя сеть и имена `.local`, `.lan` → напрямую.
2. Заблокированные в России СМИ (набор `category-media-ru-blocked`) → **всегда через VPN, даже если домен `.ru`**. Эти сайты нельзя пускать напрямую — не откроются.
3. Ваш список «всегда через VPN».
4. Ваш список «всегда напрямую».
5. Программы мимо VPN (по имени исполняемого файла).
6. Российские зоны `.ru`, `.рф` (записывается как `xn--p1ai`), `.su` → напрямую.
7. Российские наборы доменов (Яндекс, VK, Mail.ru, Госуслуги, банки, магазины и др.) → напрямую.
8. Российские IP-адреса → напрямую.
9. Всё остальное → через VPN.

Решения:
- **Российские IP-адреса сопоставляются только там, где адрес известен заранее** (в туннеле и для прямых IP). Я намеренно не использую действие `resolve`: если бы удалённый DNS на миг не ответил, движок **отвергал бы вообще все соединения** (проверил по исходникам). Надёжность важнее.
- Если домен `.ru` заблокирован в России (бывает), добавь его в «всегда через VPN».
- Вшитый набор списков лежит в `resources/rules` (источник и дата — в `SOURCE.md`). Обновляются сами раз в 3 дня; битый скачанный файл не ломает запуск — берётся вшитый.

## 9. DNS

- Для российских сайтов — «прямой» DNS (по умолчанию системный), для остальных — DoH `1.1.1.1` **через VPN**: провайдер не видит, какие зарубежные сайты вы открываете.
- Выключатель «защита от утечки DNS»: выключено — всё спрашивается у прямого DNS.
- Адрес сервера VPN, если он задан именем, ищется прямым DNS (иначе курица и яйцо).

## 10. Внешний вид

- Три набора: **Сияние** (бирюза + фиолет), **Закат** (коралл + малина), **Хвоя** (изумруд + золото) — в тёмной и светлой темах. Цвет ошейника у собаки подстраивается под набор.
- Шрифт Manrope (SIL OFL) лежит внутри программы.
- Уровни анимации: «Все», «Спокойные» (без тяжёлых фоновых эффектов) и «Выключены» — для слабых компьютеров. Подсказка у настройки это объясняет.
- Анимация большой кнопки у каждого состояния своя: выключено — «дышит»; подключаюсь — крутятся дуги, частицы слетаются к центру; работает — расходятся волны, летают точки, вспышка при включении; ошибка — вздрагивает.

## 11. Шелти (собака-помощник) — добавлено по просьбе

- Нарисована кодом (SVG), без чужих картинок: соболиный шелти с белым воротником.
- Живёт внизу боковой панели. Следит глазами и головой за курсором, моргает, дремлет, если долго не трогать мышь, виляет хвостом, когда VPN работает, прижимает уши при ошибке.
- Наведите мышку на любой элемент — в облачке над собакой появится простая подсказка. Подсказки есть у меню, большой кнопки, переключателя режимов, плиток, графика, карточек серверов, настроек.
- Облачко намеренно сделано **над собакой, внутри боковой панели**: так оно никогда не закрывает то, на что вы навели мышку.
- Выключается в «Настройках» → «Помощник».

## 12. Проверка связи и ошибки

- «Подключено» показывается только после того, как через сервер реально прошёл запрос. Если за ~20 секунд связи нет — «Сервер не отвечает. Возможно, ключ устарел или введён с ошибкой».
- Все ошибки движка переводятся в человеческие фразы (`shared/humanErrors.ts`), технические подробности остаются только в журнале.
- При обрыве: если включено «Переподключаться при обрыве» — попытки с нарастающей паузой (1,5 → 3 → 6 → 12 → 30 с), пока человек не нажмёт «Выключить».

## 13. Прочее

- Окно запускается в единственном экземпляре; пока трея нет, крестик закрывает программу; когда появится трей, крестик будет сворачивать в него, а выход — отдельной командой.
- Уведомления Windows включены только на Windows: на Linux (где я разрабатывал) без службы уведомлений они «замораживали» программу.
- Любая непредвиденная ошибка в главном процессе не показывает системное окно с ошибкой (оно блокирует программу), а записывается в журнал.
- Ключи для проверки без настоящего сервера: тесты поднимают **настоящий sing-box-сервер на localhost** для 14 вариантов подключений и гоняют через него реальный трафик.

## 14. Права администратора (этап 2)

Режиму «Весь компьютер» нужны права администратора. Варианты были такие:
1. Всегда запускать программу «от администратора» — Windows спрашивало бы при каждом запуске. Плохо для не-айтишника.
2. Запускать с повышением только движок — не получилось бы потом его остановить из обычной программы и читать его вывод.
3. **Выбрано:** один раз (с обычным окном Windows «Разрешить?») создать задачу планировщика «запускать программу с наивысшими правами». Дальше программа запускается этой задачей **без вопросов**. Разрешение можно забрать в «Настройках».

Как это складывается:
- Человек выбирает «Весь компьютер» → программа объясняет по-человечески, зачем это нужно → «Разрешить» → Windows спрашивает один раз → программа перезапускается уже с правами и включается в нужном режиме.
- Если человек отказал в окне Windows — режим не включается, объяснение спокойное, ничего не ломается.
- Если при запуске выбран «Весь компьютер», а права ещё не получены и разрешение уже выдавалось, обычная копия сама запускает копию с правами и закрывается (так же работает и автозапуск с Windows).
- Стандартная защита Electron от второго запуска не умеет «достучаться» от обычной копии до копии с правами (Windows не пускает сообщения «вниз по уровню защиты»). Поэтому я сделал свою: первая копия слушает порт **только на 127.0.0.1** и записывает его вместе с секретным словом в файл в своей папке данных; вторая копия читает файл, просит «покажись» и закрывается.
- Задача создаётся без расписания (не стартует сама), только по запросу.

## 15. Аварийное завершение (этап 2)

Нашёл тестом: закрыть программу «не нашим» путём (завершение системы, команда «выйти» от ОС) можно было так, что движок оставался в фоне, а системный прокси Windows — включённым «в никуда» (интернет пропал бы). Сделано три слоя защиты:
1. **При любом выходе** программа останавливает движок и возвращает системный прокси.
2. **При следующем запуске** программа убирает «хвосты»: если прокси остался включённым после аварии — возвращает прежний; если в фоне остался забытый движок — останавливает его (но только убедившись, что под этим номером процесса именно наш `sing-box`, чужие процессы не трогаются).
3. Прежний системный прокси человека (например, рабочий) запоминается при включении и возвращается при отключении, а «наш» старый адрес после аварии за «прежний» не считается.

## 16. Обновление списков (этап 2)

- Списки для российских сайтов лежат вшитыми (`resources/rules`); приложение само обновляет их из GitHub раз в 3 дня (проверка при запуске, через 25 секунд, и затем раз в 6 часов). Если напрямую GitHub недоступен, а VPN включён — попытка через VPN.
- Каждый скачанный файл проверяется (метка «SRS» и размер); плохой отбрасывается. Если же набор правил по какой-то причине не принят движком, при подключении используются вшитые списки — подключение из-за списков не сломается.
- Обновлённые списки применяются при следующем подключении (движок не умеет подменять их на ходу).
