## Этап 1 — каркас, главный экран, вставка ключа, подключение в режиме прокси

### Что готово

- **Приложение запускается и работает** (Electron + React + TypeScript + Vite), название «Тропа» берётся из одного файла `brand.json`.
- **Главный экран**: одна большая кнопка с понятными состояниями — *Выключено / Подключаюсь / Работает / Ошибка* — и своей анимацией на каждое. Рядом: сервер и страна (с настоящим флагом), задержка, скорость, время работы, сколько скачано, **«Ваш адрес сейчас виден как: <страна>»**, живой график скорости.
- **«Вставить ключ»**: сам берёт ключ из буфера обмена и определяет тип. Понимает `vless` (в том числе Reality), `vmess`, `trojan`, `ss`, `hysteria2`, `tuic`, `anytls`, список ключей, готовый файл sing-box. Битый ключ — понятная фраза вместо технической ошибки.
- **Подключение в режиме «Только браузер и программы»** (системный прокси): включается и выключается, прокси в Windows прописывается и убирается сам.
- **Список серверов**: карточки с флагами, переименовать, удалить, «любимый» (звёздочка).
- **Ключи хранятся зашифрованными** средствами Windows; в журнал и на экран целиком не выводятся.
- **Три набора оформления** (Сияние, Закат, Хвоя), тёмная и светлая тема, три уровня анимации — выбираются в «Настройках». Анимаций много: переливающийся фон, частицы вокруг кнопки, вспышка при включении, «живые» числа, волна при смене темы, плавные переходы между страницами и т. д.
- **Шелти** 🐕 — по твоей просьбе. Собака внизу слева: следит за курсором, дремлет, радуется, когда всё работает, и **подсказывает простыми словами, что делает то, на что навели мышку**. Выключается в «Настройках».
- Автоматическое **переподключение при обрыве** и защита от «ложного подключено» (кнопка показывает «Работает» только когда через сервер реально прошёл запрос).

В коде уже лежат заготовки для следующих этапов (права администратора, аварийная блокировка интернета, загрузка подписок, обновление списков правил) — они написаны, но **к окну не подключены и считаются непроверенными**, пока не дойду до их этапа.

Остальное по плану ещё впереди и в окне помечено «скоро» (режим «Весь компьютер», «Мимо VPN», «Защита») или пока спрятано.

### Как это запустить на Windows

1. Поставь [Node.js 22 LTS](https://nodejs.org) (если ещё нет).
2. Открой папку проекта в терминале (PowerShell) и выполни по очереди:

   ```
   npm install
   npm run fetch:singbox -- --target win32-x64
   npm run build
   npm start
   ```

   Вторая команда скачивает официальный sing-box и **сверяет контрольную сумму**; если не совпадёт — ничего не установит.
3. Нажми **«Вставить ключ»** (предварительно скопировав ключ) и большую кнопку.

   Для разработки с автоматической перезагрузкой окна: `npm run dev`. Посмотреть только оформление в обычном браузере (с тестовыми данными): `npm run ui`.

Как проверить, что системный прокси работает: после подключения открой *Параметры Windows → Сеть и Интернет → Прокси* — там должен появиться `127.0.0.1:7890`; после отключения — пропасть.

### Что я проверил (и чем)

Всё ниже проверено на Linux с настоящим sing-box 1.14.2:

- **Разбор ключей** — 79 проверок: каждый тип (включая варианты: Reality, WebSocket, gRPC, старый и новый вид `ss`, перебор портов и т. д.), **40+ видов битых ключей** (нет адреса, порта, пароля, кривой UUID, неподдерживаемый транспорт…), мусор, подписки, чужой файл настроек.
- **Каждый собранный файл настроек прогоняется через `sing-box check`** (79 проверок: каждый тип ключа × оба режима × разные настройки) **плюс своя проверка ссылок внутри файла** — оказалось, что `sing-box check` не замечает ссылку на несуществующий выход или набор правил (это вылезло бы только при запуске).
- **Сквозной трафик через настоящий sing-box-сервер на localhost** для 14 вариантов (Shadowsocks, VLESS в разных обёртках, Reality+Vision, VMess, Trojan, Hysteria2, TUIC, AnyTLS): ключ → наш код → файл настроек → реальный запрос дошёл.
- **Правила маршрутов вживую**: российские зоны напрямую, Яндекс/VK по спискам, заблокированные СМИ через VPN, домашняя сеть, свои списки, программа мимо VPN, российские IP.
- **Режим «Весь компьютер»** — реальный перехват трафика устройством TUN на Linux (на трёх сетевых стеках) — только на тестовую подсеть, остальное не затрагивалось.
- **Жизненный цикл подключения**: подключение, скорость, ошибка при неверном ключе, обрыв и автопереподключение, отмена во время переподключения, нет прав, нет движка, битый список правил.
- **Хранилище**: в файле на диске нет ни паролей, ни идентификаторов; повреждённый файл не роняет программу.
- **Настоящее приложение** в Electron (под виртуальным экраном): 13 сценариев — вставка из буфера, подключение, трафик, отключение, шифрование на диске, перезапуск, неверный ключ, мусор в буфере, подсказки Шелти.

Итого: **206 проверок + 13 сценариев настоящего окна, все зелёные** (`npm test`, `npm run test:e2e`).

### Чего я НЕ мог проверить (честно)

- ⚠️ **Нигде не запускал на настоящей Windows.** Всё, что касается Windows, написано по документации, но не проверено: запись системного прокси в реестр и его восстановление, шифрование ключей (DPAPI), уведомления, вид заголовка окна с кнопками Windows.
- ⚠️ **Ни одного настоящего ключа поставщика у меня нет.** Проверял на собственном sing-box-сервере на localhost. Сам протокол в настоящих условиях (цензура, провайдер) не проверялся.
- ⚠️ **Определение страны («ваш адрес виден как…»)** и **обновление списков правил из интернета** в моей среде недоступны (сеть закрыта), поэтому проверены только разбор ответов и устройство. В окне при недоступности честно написано «не удалось определить».
- Скриншоты в `docs/screenshots` сняты в Chromium с тестовыми данными; настоящий Electron под Linux показывает то же.

### Что не получилось / известные ограничения

- Формат подписки **Clash (YAML)** и транспорт **xhttp** не поддерживаются (движок не умеет) — человеку об этом честно пишется.
- Подписки, проверка задержки списка и QR — этап 3. «Мимо VPN», режим «Весь компьютер» и права администратора — этап 2. Защита, трей, автозапуск, «Для специалиста», установщик — этап 4.
- Я добавил проверку связи через крошечные страницы `cp.cloudflare.com` / `gstatic.com` (через сервер) — этого пункта не было в твоём списке разрешённых обращений. Подробности и как убрать — в `РЕШЕНИЯ.md`, раздел 6.

## Этап 2 — туннель («Весь компьютер»), российские сайты напрямую, программы мимо VPN

### Что готово

- **Режим «Весь компьютер»** (туннель): переключатель на главной экране теперь рабочий. Нужны права администратора — программа **один раз** объясняет зачем (окно с понятным текстом), Windows спрашивает «Разрешить?», дальше всё запускается без вопросов. Если отказать — ничего не ломается. Забрать разрешение можно в «Настройках».
- **Страница «Мимо VPN»**:
  - «Российские сайты открывать напрямую» (включено по умолчанию): зоны `.ru`, `.рф`, `.su` и готовые списки (Яндекс, VK, Госуслуги, банки, магазины, российские IP-адреса и др.). **Заблокированные в России СМИ при этом всегда идут через VPN**, даже если у них домен `.ru`. Списки обновляются сами раз в 3 дня; кнопка «Обновить сейчас».
  - **Программы мимо VPN**: выбор из запущенных и из установленных (с иконками и поиском) + готовый набор **«Игры и лаунчеры»** (62 программы: Steam, Epic, Battle.net, Riot, EA, Ubisoft, GOG, Wargaming/Lesta, VK Play и популярные игры).
  - **Свои списки сайтов**: «всегда через VPN» и «всегда напрямую». Понимают адрес целиком (`https://www.сайт.рф/страница`), звёздочку (`*.site.ru`), кириллицу и IP-адреса/сети; то, что не поняли, подсказывают.
  - **Домашняя сеть** (роутер, принтер, телевизор) — всегда напрямую, это включено навсегда.
- Любая смена этих настроек при включённом VPN **сама перезапускает подключение** (без лишних уведомлений) и показывает «Настройки применены».
- **Защита от аварий**: программа теперь при любом выходе останавливает движок и возвращает системный прокси, а при следующем запуске убирает «хвосты» после аварийного завершения (подробности — РЕШЕНИЯ.md, раздел 15). Это нашлось тестами — до этого при «неправильном» выходе мог остаться забытый движок и пропасть интернет.
- Единственная копия программы теперь работает и между обычной копией и копией с правами администратора.

Окно «Весь компьютер» теперь затемняет всё, а Шелти подсказывает и на новых экранах.

### Как это запустить

Так же, как на этапе 1 (`npm install`, `npm run fetch:singbox -- --target win32-x64`, `npm run build`, `npm start`). Чтобы попробовать туннель: на главной экране выбери «Весь компьютер» → «Разрешить».

Как проверить, что туннель работает: на главной после подключения «Ваш адрес сейчас виден как…» покажет страну сервера; в «Параметрах Windows» прокси при этом не прописывается; игры и программы без поддержки прокси идут через VPN.

### Что я проверил (и чем)

На Linux с настоящим sing-box:
- **Правила в настоящем окне**: через интерфейс выбрана программа, включён набор игр, вписаны свои списки (с кириллицей) → прочитан **реальный файл настроек, который получил движок**: правила в правильном порядке («всегда через VPN» раньше зоны `.ru`, домашняя сеть напрямую, программы напрямую, все 31 набор списков), выключение «Российские сайты напрямую» перезапустило подключение уже без списков, и трафик продолжил идти.
- **Закрытие при включённом VPN**: быстро, движок остановлен, файл с секретами удалён.
- **Права администратора** (31 проверка, вместе с авариями): задача планировщика (XML, команды), согласие/отказ/повторный запуск, перезапуск с правами, отзыв, «замок единственной копии», список программ.
- **После аварии**: забытый настоящий процесс движка находится и останавливается; чужой процесс — нет; прокси после аварии возвращается.
- **Туннель вживую** (с этапа «основа»): настоящий перехват трафика устройством TUN на Linux.

Всего теперь: **237 проверок + 19 сценариев настоящего окна, все зелёные.**

### Чего я НЕ мог проверить (честно)

- ⚠️ **Весь режим «Весь компьютер» на настоящей Windows**: драйвер wintun, `strict_route` (защита DNS на Windows), совместимость с другими VPN/антивирусами. Конфиг этого режима проверен движком и в живом тесте на Linux, но не на Windows.
- ⚠️ **Задачи планировщика и окно «Разрешить?»**: команды и XML проверены на правильность, но я не видел, как Windows их исполняет. Если на твоём ПК обычный (не администраторский) пользователь — окно Windows спросит пароль администратора, и разрешение создастся от его имени; это нормальное поведение Windows, но проверить его я не мог.
- ⚠️ Определение запущенных/установленных программ на Windows (PowerShell, меню «Пуск», иконки): написано, разбор проверен на примерах, но не запускался на Windows. На Linux (для разработки) список запущенных работает через `/proc`.
- ⚠️ Правило «программа мимо VPN»: проверено движком на Linux; для Windows движок определяет процесс иначе, но по тому же правилу.
- Туннель на **IPv6**: по умолчанию выключен (причина — в РЕШЕНИЯХ); включается в «Для специалиста» на этапе 4.

### Что не получилось / ограничения

- «Мимо VPN» для программ в режиме «Браузер и программы» работает **только для программ, использующих системный прокси** (про это написано на самой странице). Для всех остальных нужен режим «Весь компьютер».
- Российские IP-адреса сопоставляются только там, где адрес известен заранее (в туннеле) — причины в РЕШЕНИЯХ, раздел 8.
